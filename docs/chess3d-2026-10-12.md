# Chess(3d) implementation and verification

## Scope

Chess(3d) is a separate entry next to Chess in plugin and web/mobile game lists.
The original 2D game remains unchanged. Both clients lazy-load the shared
Three.js renderer in `packages/core/components/Chess3DBoard.tsx`.

The supplied reference informed the walnut/maple board, natural light pieces,
polished dark pieces, Staunton silhouettes, straight elevated perspective,
teal surroundings, and yellow-green square highlights. Textures are seeded,
local bitmap assets generated on canvas; there are no external model or texture
downloads. Camera orbit, overhead/reset and zoom controls remain available.

Existing chess room rows keep `game_type: chess` and store the variant in
`captured.presentation: 3d`. Creation, moves, rematches and resume preserve it;
invites identify `chess_3d`. Existing multiplayer, AI and promotion flows are
reused. Legal 3D targets and check highlighting use chess.js. WebGL loss or
absence falls back to the playable 2D board. Hidden panes pause rendering;
unmount disposes geometry, textures, shadows and the GPU renderer.

- Four rules-adapter tests passed: initial FEN, coordinates, pinned moves,
  castling, en passant, promotion destinations, check and black premove targets.
- Chromium and WebKit each passed the plugin/web matrix at 300x500, 600x500,
  1200x800, 390x844 and 844x390. Checks include nonblank/colorful scene pixels,
  square framing, actual raycast moves, computer replies, camera changes and
  gestures, hidden-pane input, invite/resume metadata, rejected resign/retry,
  fresh entry, and no-WebGL fallback. Tests use a mock transport, not real
  chat, invitations or score submissions; test audio is disconnected.
- Existing game lifecycle tests passed, including quit/retry, Ear Training
  computer matches and Falling Blocks snapshot restoration.
- Universal arm64/x86_64 Slur and Slur Games AU/VST3 builds completed and
  replaced local plugins atomically with previous versions backed up.
  Both AU validations succeeded. Native compiler warnings remain pre-existing.
- iOS Simulator build/install completed on iPhone 18 Pro. The signed-in
  installed app showed the new 3D lobby, wood board and reachable safe-area
  header/back button. Normal chat history and composer loaded without key,
  enrollment or encryption-unlock UI. No production game was started or
  chat sent during this native inspection.
- Android release APK built and signed; signature verification succeeded.
- Local download archives refreshed under `artifacts/games-audit/downloads`.

## Limits

- Running Logic was not quit or its project modified. AU validation and
  installed bundle contents were verified, but the refreshed plugin was not
  opened and played inside the user's current DAW session. Reopening the
  plugin/host may be needed to use the updated loaded binary.
- Android's connected emulator was offline, so native installation and
  post-login Android gameplay were not verified. The signed APK is ready.
- iOS verification used the signed-in simulator, not a physical device or
  App Store distribution build. Native multiplayer gameplay was not exercised.
- Two-account live network matches and server-authoritative rules were not
  newly audited. This change adds a renderer, not a new chess backend.
- AAX was not rebuilt or installed; existing PACE-signing requirements remain.
- Download archives were refreshed locally; no new public GitHub release or
  store submission was created.

## Repeat

Run `pnpm test:games:chess3d:rules` and `pnpm test:games:chess3d` with the QA
server on port 5191. Supply `PLAYWRIGHT_MODULE`, `SHARP_MODULE` and optional
`CHROME_PATH` when using the bundled runtime; set `GAMES_QA_ENGINE=webkit`
for WebKit. Screenshots and pixel measurements are in ignored
`artifacts/games-audit/chess3d-{chromium,webkit}`.
