# Slur 보안 구현 현황 — 2026-09-24

> 이 문서는 9월 24일 구현 시점의 기록이다. 아래의 ‘적용 전’ 상태는 당시 기준이며,
> **9월 28일 운영 반영·설치·실환경 검증 결과는 [최신 운영 적용 기록](security-rollout-2026-09-28.md)**을 기준으로 한다.

**코드와 로컬 검증을 완료한 보안 변경 묶음이다. 운영 전체 적용 완료 상태가 아니다.**
2026-09-28 추가 반영: 관리자 권한에 더해 아바타 소유권과 내부 함수 권한도 운영 DB에
적용했다. [추가 적용 기록](security-rollout-2026-09-28.md)을 참고한다. 나머지 새 마이그레이션, API,
프런트엔드, 네이티브 변경은 이 작업 공간에 있다. 현재 Vercel 연결은 프로젝트 목록이
비어 있고 프로젝트 조회 도구의 입력 규격 오류도 발생한다. CLI와 브라우저는 로그아웃 상태다.
R2 private bucket, 서버 환경변수, 실제 두 사용자 간 통신은
운영 환경에서 검증하지 못했다. 실행하지 않은 배포나 데이터 이전을 완료로 계산하지 않는다.

## 로그인 장애

보안 정책 때문이 아니라 설치된 Slur 번들에 Supabase 공개 설정이 빠져
`null.auth.signInWithPassword`를 호출하던 빌드 문제였다.
수정 AU/VST3를 설치하고 Logic 프로젝트를 저장한 뒤 Logic을 다시 실행했다.
이메일이 채워진 로그인 화면을 열어 두었다. 비밀번호 입력란은 비어 있으며,
실제 로그인 성공은 아직 확인하지 못했다. 비밀번호를 읽거나 변경하지 않았다.
상세 근거와 이전 바이너리 백업은 `incident-slur-login-2026-09-24.md`에 기록했다.

설치된 Slur의 빌드 원본은 별도 `slur-chat-track-export` 작업 공간이다.
그곳에는 로그인 수정만 반영했다. 아래 보안 변경을 설치된 Slur에도 넣으려면
해당 배포 브랜치와 네이티브 리소스 공급자 변경을 통합하고 새 클라이언트를 배포해야 한다.
이 공간에서 빌드한 OrbChat AU/VST3가 설치된 Slur를 대체했다고 주장하지 않는다.

## 암호화의 경계

- 서버에는 일반 채팅 평문과 복구 비밀을 보내지 않는다. 수신자 ID, 방 ID, 시각,
  대략적인 크기, 공개 키, 파일 참조 관계 등 메타데이터는 남는다.
- 복구 비밀은 32바이트 난수이며 로컬 입력으로 기기 키를 재생성한다. 개인 키는
  현재 메모리에만 보관한다. 사용자가 개인 기기를 신뢰하면 DAW 플러그인은 macOS Keychain,
  웹은 추출 불가능한 WebCrypto AES-GCM 키와 IndexedDB에 보관하며, 앱 재실행과 재로그인 때
  자동으로 연다. 원문을 localStorage나 서버에 저장하지 않는다. 새 기기·기기 기억 해제·브라우저
  저장소 초기화 때만 복구 키가 필요하며, 서버가 복구 키를 재설정하는 기능은 없다.
- 첫 공개 키를 신뢰하고 이후 변경을 거부한다. 첫 연결 시 서버를 통한 키 바꿔치기까지
  막으려면 당사자가 별도 신뢰 채널로 보안 번호를 비교해야 한다.
- **Double Ratchet, forward secrecy, 기기별 키와 분실 기기만 선택적으로 폐기하는
  기능은 구현하지 않았다.** 복구 비밀이 유출되면 해당 키로 감싼 과거 메시지와 이후
  메시지를 보호할 수 없다. 이 구현을 Signal과 동등하거나 독립 검증된 프로토콜이라고
  설명해서는 안 된다. 일반 서비스에 강제 적용하기 전에 암호 설계 검토가 필요하다.
- 퇴장자는 이후 메시지 키 목록에서 제외된다. 새 참가자는 그 전에 자신에게 키가
  발급되지 않은 메시지를 복호화할 수 없다. 이미 읽거나 저장한 사본은 회수할 수 없다.
- 이전 기록은 사용자가 전환하기 전까지 평문이다. 다른 작성자의 기록은 그 작성자의
  전환이 필요하다. 소유권/원본 확인이 안 되는 자료는 자동으로 공개하거나 삭제하지 않는다.
- 라이브 미디어는 WebRTC DTLS-SRTP 전송 보호를 사용한다. 중앙 SFU의 강제 연결 폐기,
  별도 insertable-stream E2EE, 서버 녹화, DRM, 대규모 CDN 방송은 구현 범위에 포함되지
  않았다. 악의적으로 변조한 송출 프로그램 자체를 강제 통제할 중앙 미디어 계층은 없다.

## 운영 반영 순서

1. Vercel을 운영 프로젝트에 접근 가능한 계정으로 연결한다. 올바른 프로젝트인지
   확인하고 현재 배포/환경 설정을 보존한다. 다른 계정의 새 프로젝트로 우회 배포하지 않는다.
2. 별도 비공개 R2 버킷을 만들고 r2.dev·custom public domain을 비활성화한다. 기존
   공개 포트폴리오와 섞지 않는다. 스코프가 제한된 R2 자격증명을 서버에 설정한다.
3. 서버 전용 환경변수: `SUPABASE_URL`, `SUPABASE_ANON_KEY`,
   `SUPABASE_SERVICE_ROLE_KEY`, `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_R2_ACCESS_KEY_ID`,
   `CLOUDFLARE_R2_SECRET_ACCESS_KEY`, `CLOUDFLARE_R2_BUCKET`,
   `CLOUDFLARE_R2_PRIVATE_BUCKET`, `R2_PUBLIC_URL`,
   `CLOUDFLARE_CALLS_TURN_TOKEN_ID`, `CLOUDFLARE_CALLS_TURN_API_TOKEN`, `CRON_SECRET`.
   공개 클라이언트에는 Supabase URL/anon key 등 공개 설정만 넣는다. service-role은 절대
   `VITE_`/`NEXT_PUBLIC_` 변수나 네이티브 번들에 넣지 않는다.
4. API `ALLOWED_ORIGINS`에는 실제 plugin/web origin과 `juce://juce.backend`,
   `capacitor://localhost`를 설정한다. R2 CORS는 해당 origin들의 PUT/GET/HEAD와
   Content-Type/If-None-Match/Range를 허용한다. 네이티브 WebView의 실제 Origin을
   확인한다. JWT 검사는 CORS와 별도로 유지한다.
5. 운영 스키마 복제 테스트 환경에서 순서대로 마이그레이션을 실행한다. 관리자 파일은
   이미 적용된 운영 버전 `20260923185345_security_admin_roles.sql`로 이름을 맞췄으므로
   중복 적용하지 않는다. 기존 원격 마이그레이션 이력과 로컬 이력의 차이도 먼저 확인한다.
6. API·웹·플러그인과 DB의 강제 E2EE 정책을 **같은 릴리스로 전환**한다. 구형 클라이언트는
   평문 INSERT/직접 방 생성/공개 신호를 사용하므로 새 DB 정책에서 거부된다.
   모든 지원 배포 브랜치/설치 바이너리에 새 버전이 제공되기 전 DB만 먼저 바꾸지 않는다.
7. 테스트 계정 두 개로 키 등록, 텍스트/이미지/오디오/다중 스템 전송, 기기 재실행·복구,
   파일 삭제·탈퇴·세션 취소, 라이브 초대·차단·네트워크 중단을 검증한다. 등록되지 않은
   수신자가 있으면 평문으로 우회하지 않고 설정 안내를 표시하는지 확인한다.
8. 구형 Supabase attachments를 비공개화하고 새 서명 경로로 21개 구형 참조를 점검한다.
   소유자 증거가 없는 참조는 별도 확인한다. R2는 manifest inventory를 만들고 공개
   포트폴리오 재사용을 분류한 후 `--apply`, 사본 검증 후 `--purge-public`을 실행한다.
   기존 공개 도메인/CDN 캐시도 정리하고 익명 GET 차단을 실제 확인한다.
9. `security-cleanup`을 서버 CRON_SECRET으로 정기 호출한다. 기존 Supabase
   `cleanup-attachments` 진입점은 같은 비밀로 내구성 있는 worker에 위임하도록 바꿨다.
   정기 실행 주기/플랜 제한을 확인하고 처리량 25개/종류/실행보다 유입이 많으면 확장한다.
   실패·오래된 pending job·스토리지 사용량·TURN 비용 경보를 운영 도구에 연결한다.
10. 이전 평문 기록을 작성자가 배치 전환한다. 백업/PITR/CDN/로그의 보존 및 실제 폐기,
    개인정보 고지/처리위탁, 운영자 접근 검토와 복구 훈련을 완료한다. 코드 수정만으로
    법적 준수나 보안 인증 완료를 선언하지 않는다.
