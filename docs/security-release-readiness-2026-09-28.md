# Slur 정식 출시 보안 준비도 — 2026-09-28 KST

## 판정

이번 변경은 공개 출시 후보에 필요한 애플리케이션 보안 통제를 구현한다. 채팅·첨부파일의 종단간 암호화, 사용자 및 관리자 권한, 라이브 입장과 TURN 릴레이, 계정 삭제와 저장소 정리는 자동 테스트와 운영 상태 점검 대상으로 묶였다.

다만 현재 Supabase 프로젝트가 Free 플랜이고 외부 침투 테스트와 암호 설계 감사를 받지 않았다. 아래 출시 차단 조건을 해소하기 전에는 대규모 공개 출시를 완료했다고 표시하지 않는다.

## 이번 보강

- 복구 키를 처음 만들 때 사용자가 한 번 더 입력해야 암호화 키를 등록한다.
- 페이지 종료, 로그아웃, 계정 전환, 세션 거부 시 메모리의 채팅 비밀키와 복호화된 파일 URL을 폐기한다.
- 사용자는 활성 로그인 목록을 보고 다른 세션을 선택적으로 차단할 수 있다. 차단된 세션은 RLS, 채팅·파일 API, 라이브 신호와 TURN 자격증명 갱신에서 거부된다.
- Cloudflare TURN 자격증명을 세션별로만 보관하고 만료 2분 전에 갱신한다. 갱신이나 권한 확인이 실패하면 미디어를 닫는다. WebRTC는 계속 `iceTransportPolicy: relay`만 허용한다.
- 파일 삭제와 계정 삭제 작업의 마지막 정상 실행 시각 및 반복 실패를 서버 상태 점검에 포함한다.
- GitHub Actions가 10분마다 인증, 비공개 R2, 삭제 작업 상태를 검사한다. 점검 토큰은 Vercel과 GitHub의 암호화된 Secret으로만 보관한다.
- 익명 호출이 가능했던 재생수 증가 RPC를 차단했다. 사용자명 확인 RPC는 3–20자의 소문자, 숫자, 점, 밑줄만 검사하고 행 데이터는 반환하지 않는다.
- 플러그인과 웹의 로그인·가입에 Cloudflare Turnstile을 적용했다. Supabase Attack Protection이 서버에서 토큰을 검증하며, 허용 호스트는 운영 웹과 플러그인 웹뷰 호스트로 제한했다.

## 운영 인증 설정

- 최소 비밀번호 12자
- 소문자·대문자·숫자·기호를 각각 한 자 이상 요구
- 비밀번호 변경 시 최근 로그인과 현재 비밀번호 확인
- 이메일 확인 유지, 이메일 OTP 유효시간 900초, OTP 길이 8자리
- IP별 로그인·가입 및 OTP 검증을 각각 5분당 10회로 제한
- Cloudflare Turnstile CAPTCHA 활성화 및 Supabase 서버 검증
- TOTP MFA 사용 가능, AAL1 세션 15분 제한 유지, 사용자당 MFA 요소 최대 3개

## 자동 검증

- `pnpm test:security`: 실제 SQL 마이그레이션, RLS/RPC, E2EE 메시지와 파일 변조, 라이브 권한, 세션 폐기, TURN 갱신, 삭제 작업 상태를 검사한다.
- plugin과 web TypeScript 전체 검사를 실행한다.
- production 배포 후 `/api/security-cleanup`과 `/api/security-status`를 운영 Secret으로 호출해 데이터베이스·R2·Auth 경계를 함께 확인한다.

## 공개 출시 전 차단 조건

1. Supabase Pro 이상으로 전환해 유출 비밀번호 차단, 단일 세션 또는 시간 제한·비활성 세션 만료를 서버 자체 기능으로도 켠다. 현재 앱 수준 세션 폐기와 30초 확인은 구현되어 있다.
2. Supabase Free 프로젝트의 쿼터 초과 시 요청 중단 위험을 제거한다.
3. 독립된 침투 테스트와 암호 구현 검토를 받고, 발견 사항을 수정한 뒤 재시험한다.
4. 장시간 라이브, 네트워크 전환, 호스트 종료, 권한 회수, TURN 갱신을 실제 서로 다른 네트워크와 지원 DAW에서 검증한다.
5. 법률 전문가가 개인정보 처리방침, 보존 기간, 이용자 삭제·열람 절차, 사고 통지 절차를 출시 국가 기준으로 검토한다.
6. AAX를 일반 Pro Tools에 배포하려면 PACE Eden 개발자 서명 자격과 제품 `wcguid`를 발급받아 릴리스 번들을 서명한다. 현재 AAX SDK 빌드는 가능하지만 해당 자격은 없다.

## 암호 설계의 범위

현재 채팅은 서버가 평문을 읽지 못하는 사용자별 장기 복구 키 기반 봉투 암호화를 사용한다. 서명, 참여자 공개키 고정, 메시지 및 대화 식별자 바인딩, 첨부파일 스트리밍 인증 암호화를 제공한다. Signal Double Ratchet 계열의 메시지별 전방향 안전성, 기기별 키, 안전한 다중 기기 키 이전은 아직 포함하지 않는다. 이 기능이 필요한 위협 모델이면 공개 출시 범위와 별도로 프로토콜 설계와 독립 감사를 진행한다.

이 문서는 기술 통제와 검증 상태를 기록한다. 법적 인증이나 무침해를 보증하지 않는다.
