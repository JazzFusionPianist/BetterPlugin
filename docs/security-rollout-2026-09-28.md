# Slur 보안 운영 적용 기록 — 2026-09-28 KST

> 2026-10-03: 아래 채팅 E2EE/복구키 정책은 [계정 기반 채팅](account-chat-2026-10-03.md)으로 대체됐다. 이 문서는 당시 적용 기록이다.

**서버·웹·DB 운영 전환과 Slur 1.0.24 설치를 적용했다.**
‘전체 운영 전환’은 테스트 코드만 준비하는 것이 아니라 실제 서비스 주소, 데이터 접근 정책,
저장소, 정리 작업, 설치된 클라이언트가 새 보안 경로를 함께 사용하도록 바꾸는 것을 뜻한다.
모든 미래 보안 과제나 법적 준수까지 완료했다는 뜻은 아니다.

## 적용한 기능

- 일반 DM/그룹의 새 메시지와 첨부파일은 클라이언트에서 종단간 암호화한다.
  서버는 암호문과 전달에 필요한 메타데이터를 보관한다. 평문 새 메시지 쓰기는 차단한다.
- 방 참여자·관리자 권한, 탈퇴·차단·취소된 로그인 세션을 서버/DB에서 확인한다.
  관리자 권한은 별도 원장과 MFA 확인을 사용한다.
- 파일은 비공개 저장소에 두고, 현재 접근 권한을 확인한 뒤 만료되는 다운로드 주소를 발급한다.
  업로드 덮어쓰기·임의 파일 참조·잘못된 크기/형식·과도한 요청을 제한한다.
- 라이브는 입장·초대·강퇴·송출자 권한과 신호 발신자를 서버에서 확인한다.
  권한이 있는 참가자만 TURN 중계 자격증명을 발급받는다. WebRTC는 relay-only로 구성했다.
- AI에는 사용자가 선택하고 동의한 내용만 전달한다. 네이티브 브리지·다운로드 대상,
  브라우저 보안 헤더, 아바타 소유권, 내부 DB 함수 실행 권한을 제한했다.
- 계정/파일 삭제와 중단 업로드 정리를 재시도 가능한 작업으로 처리한다.
  계정 삭제 후 프로필이 남던 운영 DB 문제도 보완했다.

## 실제 운영 반영

Supabase 프로젝트 `svhjgiloekkjrcefclqs`에 관리자 권한, 아바타 소유권,
내부 함수 권한, 파일 접근, 라이브, E2EE, 멤버십/세션, 과거 기록 전환,
삭제 큐, 레거시 저장소, 안전한 R2 이전 후보 확인, 프로필 삭제 마이그레이션을 적용했다.
저장소 `attachments`는 비공개다. `parse-schedule` 및 `cleanup-attachments` 함수도 배포했다.
마이그레이션 파일명은 실제 운영 적용 버전과 일치시켰다.

Cloudflare의 새 `slur-private-files` 버킷은 공개 주소와 공개 도메인을 사용하지 않는다.
CORS는 운영 웹/플러그인과 네이티브 origin만 허용한다. 사용자가 승인한 기존 서버 토큰의
Object Read & Write 범위는 기존 `coop-chat-attachments`와 새 비공개 버킷 두 곳이다.
서버 비밀값은 클라이언트 번들이나 Git에 포함하지 않았다.

- 웹: https://orb-app-liard.vercel.app

- web: `orb-pri2q9abq-jazzfusionpianists-projects.vercel.app`

`/api/security-cleanup`은 5분 간격 운영 스케줄에 등록했고, 인증된 수동 호출도 정상 응답했다.
RPC가 정상적으로 빈 본문을 반환할 때 서버가 JSON 파싱 오류를 내던 문제를 수정하고 배포했다.

## 기존 파일 이전 결과

기존 공개 R2 객체 38개를 DB의 채팅·포트폴리오 참조와 대조했다.

| 분류 | 처리 |
|---|---|
| 비공개 채팅 등의 참조가 있는 파일 33개 | 비공개 복사 → 크기/ETag 검증 → DB 경로 전환 → 공개 원본 제거 |
| 공개 포트폴리오 사용 파일 1개 | 공개 상태 유지 |
| 연결된 기록이 없는 파일 4개 | 비공개로 복사·검증 후 공개 원본 제거, 자동 삭제되지 않도록 quarantined 보관 |
| 원래 객체가 없던 DB 참조 7개 | 원본 부재 기록, 임의 데이터 생성·참조 삭제하지 않음 |

총 **37개 이전 파일의 이전 공개 주소 모두 접근 차단(403/404)**을 확인했다.
복사 검증 실패 시 공개 원본을 지우지 않으며, 이전 직전에 포트폴리오 재사용 여부를 다시 확인한다.
이전 API는 운영 비밀키 인증과 서버 전용 후보 검사를 요구한다.
참조 없는 파일 4개는 사용자 기록이 확인될 때까지 비공개 격리 상태로 유지한다.
대상별 상세 결과에는 식별자가 있으므로 Git이 아닌 보호된 운영 작업 파일에만 보관했다.

**비공개 저장소 이동은 과거 파일을 소급해서 종단간 암호화하는 작업이 아니다.**
과거 채팅과 파일은 아래 사용자 기기 전환 절차를 거쳐야 한다.

## Slur 설치

기존 설치본 1.0.23의 최신 트랙/리전 내보내기 기능을 보안 작업에 통합하고 버전을 **1.0.24**로 올렸다.
별도 개발 작업 공간의 원본은 수정하지 않았다. AU·VST3·AAX·Standalone을
arm64/x86_64로 빌드하고 기존 설치본을 백업한 뒤 교체했다.
Apple Developer ID로 서명하고 AAX는 기존 PACE 서명 설정으로 검증했다.

- AU: `~/Library/Audio/Plug-Ins/Components/Slur.component`
- VST3: `~/Library/Audio/Plug-Ins/VST3/Slur.vst3`
- AAX: `/Library/Application Support/Avid/Audio/Plug-Ins/Slur.aaxplugin`
- Standalone: `~/Applications/Slur.app`

이 환경의 Xcode 27 빌드는 macOS 12 이상 대상이다. 다른 Slur 제품은 교체하지 않았다.
열린 DAW나 프로젝트를 강제로 종료하지 않았다. **작업을 저장하고 DAW를 완전히 종료·재실행해야
이미 메모리에 올라온 구버전까지 교체된다.**

기존 1.0.23 AU/VST3 백업: `~/.codex/backups/slur-security-20260928-035213`.
추가 서명·전체 형식 설치 백업은 `~/.codex/backups/slur-security-all-formats-*`에 보관한다.

- 운영 DB 평문 쓰기 거부, 타인 채팅 읽기 차단, 라이브 초대/강퇴/발신자 위조 차단,
  참가자 TURN 발급 성공과 비참가자 발급 거부 확인.
- AI 동의 없는 호출 거부, 로그아웃된 세션 거부 확인.
- 테스트 계정은 삭제했으며, 이번 수정 후 테스트 프로필 잔존 수 **0**을 확인했다.
- 네이티브 서명 검증 및 `auval`의 AU VALIDATION SUCCEEDED 확인.

이 검증은 사용자의 실제 계정으로 열린 DAW 안에서 로그인했다는 뜻은 아니다.
실시간 양방향 미디어, 대용량 파일 메모리 사용, 장시간 TURN 갱신/재접속 실측은 별도다.

## 사용자가 해야 하는 전환

1. 작업을 저장하고 DAW를 재실행한다.
2. 로그인 후 ‘채팅 보안’에서 복구 키를 설정하고 안전하게 보관한다.
   이미 생성한 키가 있으면 같은 키로 잠금을 해제한다. 서버가 잃어버린 키를 복구할 수 없다.
3. 대화 상대도 키를 설정한 뒤 ‘내 이전 기록 암호화’를 실행한다.
   다른 사람이 작성한 과거 기록은 그 사람이 전환해야 한다.

복구 키 생성·보관과 개인 과거 기록 암호화는 계정 소유자 기기에서 진행해야 하므로
관리자가 대신 완료한 것으로 표시하지 않았다.

## 남은 보안 개발/운영 과제

- 현재 E2EE는 계정 복구 키와 libsodium 기반이며, Double Ratchet/전방향 안전성,
  기기별 키·선택적 기기 폐기, 독립 암호 설계 검토는 미완료다.
- 과거 평문 기록·백업/PITR 사본은 별도 보존·삭제 정책이 필요하다.
- 라이브/게임 채팅은 E2EE 대상이 아니다. 라이브 미디어에는 WebRTC 전송 보호가 적용되지만,
  별도 미디어 E2EE, SFU 강제 연결 폐기, 녹화/DRM, 대규모 방송 인프라는 추가 개발 대상이다.
- 운영 경보, 사고 대응·백업 복구 훈련, 장시간 미디어 품질/접근 차단 실측이 필요하다.
- Supabase의 유출 비밀번호 검사 비활성화와 pg_net 공개 스키마 등 advisor 항목이 남아 있다.
  일부 SECURITY DEFINER API/정책 없는 private 테이블은 제한된 서버 접근을 위한 의도된 구성이다.
- 배포만으로 법적 준수나 침해 가능성 0을 보장하지 않는다.
